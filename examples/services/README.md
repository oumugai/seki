# システム開発で seki を使うとどうなるか

`seki --audit examples/services` で 5 つのファイルを 1 枚の報告にまとめる。

いずれも「テストでは書けないが、コードを書き換えなくても言えること」を
並べてある。

| ファイル | 主張 | 使っている仕組み |
|---|---|---|
| `money.seki` | 金額の分割で 1 円も消えない・増えない | 全入力の証明、整数の離散性 |
| `ratelimit.seki` | トークンバケットが容量を超えず負にもならない | 全入力の証明、`if` の場合分け |
| `retry.seki` | ジッタ付きリトライが締切を破らない | 区間による包絡線、`width` |
| `sla.seki` | 合成可用性が SLO を満たす | 確度と出所つきの仮定、Fréchet 下界 |
| `capacity.seki` | ピーク時の容量が足りる | パラメータの箱、足りない仮定の逆算 |

## テストとの違い

テストは「この入力で動いた」を言う。ここにあるのは「**この範囲のすべての
入力で**成り立つ」で、反例が存在しないことを機械が確かめている。

`capacity.seki` から仮定を 1 つ落とすと、seki は何が足りないかを名指しする:

```
cannot prove (perNode * nodes) >= rps over Real
  it would hold given `(perNode >= 625)`
```

感度分析の表を読んで気づくのではなく、境界が返ってくる。
